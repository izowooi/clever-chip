# AI 작업 지침 (Global AGENTS)

이 문서는 사용자의 전체 개발 환경에서 공통으로 적용하는 전역 작업 규칙이다.
저장소별 지침이 별도로 존재하면 이 문서보다 우선한다.

AI 에이전트는 작업 시작 전에 이 문서를 읽고, 현재 저장소의 맥락과 함께 해석한 뒤 작업한다.

## 사용자 작업 환경

사용자의 모든 git 저장소는 기본적으로 아래 경로 아래에 있다.

```text
/Users/izowooi/git
```

별도 지시가 없다면 새 저장소를 만들지 않는다.
커밋과 푸시는 기본적으로 현재 브랜치 또는 사용자가 명시한 브랜치에 수행한다.
브랜치 지시가 없고 현재 브랜치가 `main`이면 `main`에 직접 커밋하고 푸시한다.

## 작업 시작 전 필수 확인 사항

작업 시작 전 아래 파일이 존재하면 먼저 읽는다.

우선순위:

1. `/Users/izowooi/git/REPOS.md`
2. 프로젝트 루트의 `AGENTS.md`, `CLAUDE.md`
3. 프로젝트 루트의 `README.md`
4. 프로젝트 루트의 `package.json`

전역 지침과 프로젝트별 지침이 충돌하면 프로젝트별 지침을 우선한다.
프로젝트 구조, 역할, 실행 방법, 배포 방식을 이해한 뒤 작업한다.

## 작업 범위

- 요청받은 범위 안에서만 수정한다.
- 관련 없는 파일, 폴더, 설정은 임의로 변경하지 않는다.
- 이미 존재하는 사용자 변경사항을 되돌리지 않는다.
- 작업 중 발견한 별도 이슈는 필요하면 제안하되, 요청 범위 밖이면 임의로 수정하지 않는다.
- 불확실한 요구사항은 합리적으로 추론하되, 위험하거나 되돌리기 어려운 결정은 먼저 확인한다.

## 모노레포 작업 규칙

모노레포 구조를 선호한다.

새 프로젝트나 패키지를 만들 때는 다음 순서를 따른다.

1. `/Users/izowooi/git/REPOS.md`가 있으면 리포지토리 정보를 확인한다.
2. 기존 폴더 구조와 naming convention을 분석한다.
3. 관련 있는 서브 폴더 또는 workspace 위치를 선택한다.
4. 루트 구조 변경이 필요하면 이유를 설명하고 최소 변경으로 진행한다.

기존 모노레포에서는 package manager, workspace 구성, lint/test/build 규칙을 먼저 확인한다.

## Git 작업 규칙

작업 완료 후 기본적으로 아래 순서를 따른다.

1. 변경 내용 확인
2. 정적 분석
3. 테스트
4. 빌드
5. `git status` 확인
6. `git add`
7. `git commit`
8. `git push`

문서만 수정한 경우처럼 정적 분석, 테스트, 빌드가 의미 없으면 생략하고 그 이유를 응답에 남긴다.
커밋 전에는 의도한 파일만 staging 되었는지 확인한다.

## Commit Message 규칙

커밋 메시지는 짧고 명확한 한글로 작성한다.
기술 용어는 영어를 그대로 사용한다.

권장 형식:

```text
전역 AGENTS 작업 지침 정리

- 작업 시작 전 확인 순서 명확화
- Git 작업 및 보안 규칙 보강
- 응답 스타일과 작업 철학 정리
```

## 코드 스타일

아래 방향을 선호한다.

- TDD 개발 방법론 우선
- 단순한 구조
- 과도한 abstraction 지양
- dependency 최소화
- 가독성 우선
- 유지보수성 우선
- 기존 코드 스타일과 프로젝트 관례 존중

## 보안 규칙

아래 작업은 자동으로 수행하지 않는다.
필요하면 목적, 영향 범위, 되돌리는 방법을 설명하고 사용자 승인을 먼저 받는다.

- `rm -rf` 실행
- force push
- SSH key 수정
- macOS 시스템 설정 변경
- API key, token, secret 출력
- `.env` 덮어쓰기
- 결제 수행
- 유료 리소스 생성
- 요청 범위 밖의 데이터 외부 업로드

민감 정보가 포함될 수 있는 파일은 출력, 커밋, 업로드 전에 특히 주의한다.

## 응답 스타일

사용자는 다음 특성을 가진다.

- 기술 이해도가 높다.
- 설명을 좋아한다.
- CLI 환경에 익숙하다.
- 자동화와 생산성을 중요하게 생각한다.

따라서 다음 원칙을 따른다.

- 불필요한 기초 설명은 줄인다.
- 명령어를 제안하거나 실행할 때는 목적과 영향 범위를 간단히 설명한다.
- command 예제는 바로 실행 가능한 형태로 제공한다.
- 실제 운영 관점의 리스크와 확인 방법을 함께 제시한다.
- 작업 결과는 변경 요약, 검증 결과, 남은 이슈 중심으로 정리한다.

## AI 작업 철학

- 반복 작업 최소화
- 자동화 가능성
- 유지보수성
- 확장성
- 안전성
- 사용자의 기존 맥락과 선호 존중
