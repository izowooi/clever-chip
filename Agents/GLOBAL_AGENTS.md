# L1 AGENTS.md

이 문서는 `/Users/izowooi/git` 워크스페이스에 진입하는 모든 작업에 공통 적용되는 전역 작업 지침이다.
하위 경로에 별도 `AGENTS.md`가 있으면 더 구체적인 하위 지침을 우선한다.

## 워크스페이스 컨텍스트

- `/Users/izowooi/git`은 자체 `.git`이 없는 워크스페이스다. 다수의 독립 git 저장소를 담는 컨테이너로 운영된다.
- 자식 저장소 중 `RisuAI/`, `clever-chip/`, `crispy-web/`, `playground/`는 자체 L3 `AGENTS.md`를 보유한다. L1과 충돌하면 자식 L3 지침을 우선한다.
- 저장소 인덱싱은 같은 경로의 `REPOS.md`를 참조한다. workspace 운영 규칙(naming convention·새 저장소 생성 기준 등)은 별도로 정의하지 않으며, 필요 시 추후 본 문서나 `REPOS.md`에 추가한다.

## 기본 작업 철학

- 세부적인 구현보다는 전체에서 바라보는 관점을 우선시 한다.
- TDD 개발 방법론을 우선한다. 단, 기존 코드 스타일과 프로젝트 관례를 더 우선한다.
- 테스트가 어려운 영역은 수동 검증 절차를 응답에 명시한다.
- 단순한 구조를 선호하고, 과도한 abstraction을 피한다.
- 새 dependency 추가는 보수적으로 판단한다. 영향 범위와 대안을 먼저 검토하고, 추가 의도와 이유를 설명한 뒤 진행한다.
- 표준 라이브러리와 기존 의존성을 우선한다.

## AI 자율성 수준

기본 모드는 자동화 우선이다. 코드 수정·테스트·빌드·커밋·push까지 자율적으로 수행한다.
단, 아래 작업은 사용자 승인 후에만 진행한다.

- force push
- secret, token, API key의 수정 또는 출력
- 운영 배포 / 운영 데이터 외부 업로드
- 대량 삭제 또는 `rm -rf` 류 비가역 삭제
- 외부 서비스로 데이터 업로드
- 유료 리소스 생성 / 결제 수행
- macOS 시스템 설정 변경
- `.env` 덮어쓰기

## 작업 범위

- 요청받은 범위 안에서만 수정한다.
- 관련 없는 파일·폴더·설정은 임의로 변경하지 않는다.
- 이미 존재하는 사용자 변경사항을 되돌리지 않는다.
- 작업 중 발견한 별도 이슈는 제안만 하고, 요청 범위 밖이면 임의로 수정하지 않는다.
- 불확실한 요구사항은 합리적으로 추론해 진행한다.
- 되돌리기 어려운 결정(파일 삭제, 외부 호출, 운영 영향, 비가역 마이그레이션 등)은 진행 전 사용자에게 확인한다.

## 작업 전 확인 순서

작업 시작 전 아래 파일이 존재하면 먼저 읽는다.

1. 현재 경로와 상위 경로의 `AGENTS.md`
2. 프로젝트 루트의 `CLAUDE.md`
3. 프로젝트 루트의 `README.md`
4. 프로젝트 루트의 package/config 파일 (`package.json`, `pyproject.toml`, `Cargo.toml` 등)
5. CI/CD 관련 파일 (`.github/workflows/`, `.gitlab-ci.yml` 등)

상위 지침과 하위 지침이 충돌하면 더 구체적인 하위 지침을 우선한다.

## Git 규칙

- 작업 전후로 `git status`를 확인해 작업 트리 상태를 파악한다.
- staging은 의도한 파일만 명시적으로 지정한다. `git add .` 류의 광역 staging은 지양한다.
- 커밋 메시지는 짧고 명확한 한국어 또는 영어로 작성하되, 명령어·플래그·라이브러리명 등 기술 용어는 영문 그대로 둔다.
- 문서만 수정한 경우 테스트·빌드 단계를 생략할 수 있으며, 생략 사유를 응답에 한 줄로 남긴다.

## 코드 스타일

- 성급한 공통화보다 명확한 중복을 선호한다.

## 보안 규칙

- 자동 commit/push, 민감 파일 블록리스트, 새 저장소·브랜치 생성 정책은 글로벌 `~/.claude/CLAUDE.md`의 절대 원칙을 따른다. 본 문서에서 반복하지 않는다.
- 민감 정보가 포함될 수 있는 파일은 출력·커밋·업로드 전에 특히 주의한다.

## 응답 스타일

- CLI에 익숙한 사용자를 전제로 한다.
- 핵심 명령과 변경 요약을 먼저 제시한다.
- 영향 범위와 잠재 리스크를 함께 짚는다.
- 장식적 문장과 과도한 사과·반복 표현은 피한다.

## 문서화 선호도

- 네이밍과 구조로 의도를 먼저 표현한다.
- 주석은 비자명한 WHY를 설명할 때만 추가한다. 코드만 봐도 알 수 있는 사실(WHAT)은 주석으로 옮기지 않는다.
- `README.md`는 사용자가 명시적으로 요청하거나 외부 사용자가 진입할 때만 작성·갱신한다.

## 테스트·빌드 실패 시 행동

- 실패가 발생하면 근본 원인을 추적해 수정한다.
- `--no-verify`, hook 우회, 테스트 스킵 같은 일시 우회는 금지한다. 사용자가 명시적으로 요청한 경우에만 예외로 허용한다.
- 환경 문제로 의심되면 사용자에게 환경 확인을 먼저 요청한다.

## 지속 개선 규칙

- 반복되는 사용자 취향·응답 스타일 문제는 L1에 반영한다.
- 저장소 배치나 workspace 운영 문제는 L2에 반영한다.
- 특정 자식 저장소의 구조·루트 설정 문제는 해당 자식의 L3에 반영한다.
- 특정 프로젝트의 실행·테스트·빌드 문제는 L4에 반영한다.
- 반영은 `/agents-md [대상 경로]` 슬래시 명령으로 수행한다.
