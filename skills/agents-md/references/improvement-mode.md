# improvement 모드 워크플로우

기존 AGENTS.md가 있는 경로에서 스킬이 트리거됐을 때 사용하는 흐름. 가이드 1123~1151행의 "지속 개선 프롬프트"를 자동화.

## 진입 조건

Phase 0에서 `target_path/AGENTS.md` 존재 확인 시 자동으로 이 모드. 사용자가 "전체 새로 작성"을 명시 요청하면 `create` 모드로 전환 후 백업 표시 ON.

## 단계

### Step 1. 기존 AGENTS.md 파싱

- 파일 읽기
- 헤더 계층(`#`/`##`/`###`)으로 섹션 분할
- 각 섹션의 첫 줄 + 마지막 줄 추출
- 가이드 권장 섹션 구조와 매칭 → 누락 섹션 식별

### Step 2. Analyst 호출 (간소화)

create 모드와 동일하게 호출하되, Analyst가 추가로:
- 기존 AGENTS.md 명령어 후보들이 **여전히 유효한지** 검증 (예: `npm run dev`가 package.json에 아직 있는지)
- 기존 파일 작성 이후 추가된 새 파일·기술 스택 식별 (Git 변경 이력 확인 가능하면)

산출물: `01_analyst_report.md`에 "기존 AGENTS.md 분석" 섹션 추가.

### Step 3. 핵심 인터뷰 질문

create 모드의 계층별 질문은 **건너뛴다**. 대신 사용자 의도 중심 질문:

**Q1 (plain text):** "AI 작업 중 마음에 들지 않았던 행동이 있나요? 또는 추가/수정하고 싶은 규칙이 있나요?"

사용자가 자유 서술. 답변이 비어있거나 "특별히 없음"이면 Step 4로 (자동 점검만).

**Q2 (Q1 답변 후, 분류 확인용):** Q1 답변을 Phase 가이드 1131~1138행 규칙으로 분류:
- 전역 취향 문제 → L1
- 저장소 배치/workspace 문제 → L2
- 모노레포 구조/운영 문제 → L3
- 특정 프로젝트 실행/검증 문제 → L4

분류 결과를 사용자에게 확인:
```
이 피드백은 {L계층}에 반영해야 할 것 같습니다 — 현재 작업 중인 파일과 일치합니다.
A. 이대로 진행 (추천)
B. 다른 계층(다른 AGENTS.md)에 반영해야 함 → 스킬 중단, 사용자 안내
```

**Q3 (Step 3 추가 가능):** "어느 섹션을 어떻게 고칠지" 구체 질문 — Analyst가 발견한 기존 섹션 목록 제시:
```
어느 섹션을 수정/추가할까요?
A. {기존 섹션 A}
B. {기존 섹션 B}
C. 새 섹션 추가
```

### Step 4. 자동 점검 (기존 파일 품질 검사)

Writer를 우회하고 **Reviewer를 먼저 호출** — 기존 AGENTS.md를 입력으로:

```
Agent(
  subagent_type: "general-purpose",
  description: "AGENTS.md existing file review",
  model: "opus",
  prompt: <draft_path=기존 AGENTS.md, round=1, layer 전달>
)
```

산출물: `04_reviewer_report_v1.md` — 기존 파일에 대한 진단.

이 리포트를 사용자에게 보여주고 다음 질문:
```
기존 파일에 다음 이슈가 발견되었습니다 (요약):
- 수정 필요: {N}건
- 제거 권장: {N}건

A. Q1 피드백 + 이 이슈를 함께 반영해 수정
B. Q1 피드백만 반영, 기존 이슈는 무시
C. 취소
```

### Step 5. Writer를 diff 모드로 호출

- 입력에 기존 AGENTS.md + Q1 피드백 + (선택) Reviewer 리포트
- Writer 프롬프트 보강: **"기존 파일의 통과 섹션은 그대로 유지하고, 수정 필요 섹션만 정확히 보정. 새 섹션은 사용자가 명시한 위치에만 추가."**
- 출력: `03_writer_draft_v1.md` (수정된 전체 마크다운)

### Step 6. Reviewer 라운드 1 (수정본 검토)

create 모드 Phase 5와 동일. 라운드 2까지 진행.

### Step 7. Phase 6 (사용자 승인)

create 모드와 동일하지만, **사용자에게 diff 형식으로 변경점 강조**:
```bash
diff <기존 AGENTS.md> <draft>
```

사용자가 변경점을 한눈에 볼 수 있도록 메인 스레드가 diff를 출력. (큰 diff면 통계만 + 주요 hunk 3개)

### Step 8. 저장 (Phase 6 A 선택 시)

create 모드와 동일. 백업은 `.bak.{YYYY-MM-DD_HHMM}` 형식 강제.

## 사용자 의도 분류 (Q2 매핑 상세)

가이드 1131~1138행 원본:
- "전역 취향 문제" → L1: "응답이 너무 길어", "주석을 너무 많이 단다"
- "저장소 배치 문제" → L2: "새 저장소를 마구 만든다", "REPOS.md 안 본다"
- "모노레포 구조 문제" → L3: "루트 lockfile을 함부로 수정한다", "서브폴더 사이 결합도 무시"
- "특정 프로젝트 문제" → L4: "이 프로젝트 테스트 명령을 매번 헷갈려한다", "API key를 콘솔에 출력한다"

분류가 모호하면 사용자에게 확인.

## 다른 계층 이동 (Step 3 B 선택 시)

사용자 피드백이 현재 작업 중인 AGENTS.md 계층이 아닌 다른 계층에 속하면:
- 현재 스킬 중단
- 사용자에게 안내: "이 피드백은 {다른 계층}의 AGENTS.md(`{path}`)에 반영해야 합니다. 해당 경로에서 `/agents-md` 다시 실행해주세요."

## 출력 위치

- create 모드와 동일: `target_path/AGENTS.md`
- 백업: `target_path/AGENTS.md.bak.{YYYY-MM-DD_HHMM}`
