# L2 워크플로우

L2는 여러 git 저장소가 모인 workspace 단위 운영 규칙. 1개만 존재.

## Analyst 역할

- `target_path` 자식 디렉토리 enumerate
- 각 자식 중 `.git`가 있는 폴더만 별도 리스트 → 저장소 후보
- 각 저장소의 README 첫 줄 또는 package 파일 키워드로 목적 추정
- 부모 AGENTS.md(L1) 확인 — 있으면 그 내용을 인지하고 중복 회피용으로 Writer에 전달
- 자식 저장소들의 naming convention 패턴 추출 (kebab-case, snake_case 등)

## 인터뷰 질문 (6~7개)

### Q1. 저장소 기본 위치

**추천:** Analyst가 발견한 경로 (예: `/Users/{user}/git`)
**출처:** 코드 (Analyst 발견값)
**선택지:** A. Analyst 발견값(추천) / B. 다른 경로 / C. 여러 경로 사용

### Q2. 새 저장소 생성 기준

**추천:**
```text
- 새 작업 시작 전 기존 저장소 중 관련 있는지 먼저 확인
- 관련 저장소 있으면 새로 안 만들고 기존 안에서 작업
- 새 저장소 필요 시 이유와 위치를 설명하고 사용자 승인
- 모노레포 선호, 단 독립성 강하면 별도 저장소 고려
```
**출처:** 가이드 286~289행
**선택지:** A. 권장값(추천) / B. 모든 새 작업은 새 저장소 / C. 항상 모노레포

### Q3. REPOS.md 사용 여부

**추천:** "사용 — 저장소 인덱스로 활용"
**출처:** 가이드 290~296행
**선택지:** A. 사용 + 함께 생성(추천) / B. 사용하지만 나중에 / C. 사용 안 함

### Q4. 저장소 naming convention

**추천:** Analyst가 발견한 패턴 (예: kebab-case)
**출처:** 코드 (자식 저장소 이름 패턴)
**선택지:** A. 발견 패턴(추천) / B. 명시적 지정 / C. 제약 없음

### Q5. 모노레포 선호 여부

**추천:** "기본 선호, 독립성 강한 프로젝트만 별도"
**출처:** 가이드 289행, 사용자 CLAUDE.md (모노레포 강제 정책)
**선택지:** A. 모노레포 우선(추천) / B. 균형 / C. 항상 별도 저장소

### Q6. 다저장소 작업 시 커밋 분리 기준

**추천:**
```text
- 여러 저장소 동시 수정 시 변경 범위 먼저 요약
- 각 저장소별 검증 방법 분리
- 하나의 커밋으로 묶을 수 없는 작업은 저장소별로 따로 커밋
```
**출처:** 가이드 299~301행
**선택지:** A. 권장값(추천) / B. 한 트랜잭션으로 묶음 / C. 항상 사용자 결정

### Q7. (REPOS.md 사용 시에만) REPOS.md 항목 형식

**추천:**
```text
| 저장소 | 경로 | 목적 | 주요 폴더 |
|---|---|---|---|
| {name} | {abs path} | {1줄 요약} | {top folders} |
```
**출처:** 가이드 293행
**선택지:** A. 권장 테이블(추천) / B. 불릿 리스트 / C. 사용자 지정

## REPOS.md 동시 생성

Q3에서 사용 선택 시:
- Writer에게 두 산출물 동시 작성 지시
- AGENTS.md (workspace 규칙) + REPOS.md (저장소 인덱스)
- REPOS.md 템플릿: `references/templates/repos-template.md`
- 출력 경로: 둘 다 `target_path/` 직속

## Writer 입력 (템플릿)

`references/templates/l2-template.md`.

핵심 섹션 (가이드 261~302행):
1. 기본 저장소 위치
2. 저장소 탐색 순서
3. 저장소 선택 규칙
4. 저장소 인덱스 (REPOS.md 사용 여부 명시)
5. 여러 저장소에 걸친 작업

## Reviewer 추가 검토

- 150줄 초과 시 "수정 필요"
- 특정 저장소의 npm workspace 구조 설명 포함되면 "제거 권장" (L3 영역)
- 특정 프로젝트의 실행 명령 포함되면 "제거 권장" (L4 영역)
- 부모 L1과 중복 (TDD/응답 스타일 등) "제거 권장"

## L1 합본 운영

사용자가 Phase 1.5에서 "L1+L2 합본"을 선택한 경우:
- L1 섹션이 먼저 (개발 철학)
- L2 섹션이 뒤 (workspace 운영)
- 하나의 AGENTS.md 안에 `# Global Rules` / `# Workspace Rules` 두 H1으로 구분
- 길이 기준은 L1(250) + L2(150) = 400줄 이하

## 출력 위치

- `target_path/AGENTS.md`
- REPOS.md 동시 생성 시 `target_path/REPOS.md`
