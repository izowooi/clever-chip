# L4 워크플로우

L4는 모노레포 안의 개별 서브 프로젝트·앱·도구·서비스에 적용. 짧고 실용적이어야 함.

## Analyst 역할 (가장 무거움)

- 부모 git root + 부모 AGENTS.md (L3) 확인 → Writer 중복 회피
- `target_path`의 package 파일 정독:
  - `package.json`: name, description, scripts 전체 키-값, dependencies 주요 framework
  - `pyproject.toml`: project name, scripts, dependencies
  - `pubspec.yaml`: name, dependencies
  - `Cargo.toml`: package.name, [[bin]] / [lib]
- entrypoint 식별:
  - `src/index.ts`, `src/main.py`, `cmd/`, `main.go` 등
  - package.json의 `main`, `bin` 필드
- 실행/테스트/빌드 명령 정확한 형태 추출:
  - `npm run dev` 형태 → `package.json scripts.dev` 실제값
  - Python: `pyproject.toml [project.scripts]` 또는 entrypoint
  - Dockerfile 존재 시 `docker build` / `docker run` 명령 후보
- 외부 의존성 식별:
  - 환경 변수 참조 패턴 (`process.env.X`, `os.environ['X']`) — 키 이름만 enumerate
  - `.env.example` 존재 여부와 키 목록
  - HTTP client 사용 (axios, requests, fetch) → 외부 API 사용 가능성 플래그
- CI 워크플로 파일 — `target_path`에 직접 있는지 또는 부모 `.github/workflows`에 매칭되는 job 있는지
- 자주 깨지는 파일 후보 — lockfile, generated code, native binding 등

## 인터뷰 질문 (4개만 — 짧게)

Analyst가 대부분 채우므로 인터뷰는 코드에서 알 수 없는 항목만.

### Q1. 프로젝트 목적 (1~3줄)

**추천:** Analyst의 package.json description + README 첫 단락 기반 추정
**출처:** 코드
**도구:** plain text — 사용자가 추천 수락 또는 수정

### Q2. 외부 API / Secret 사용 여부

**추천:** Analyst가 환경 변수·HTTP client 발견 시 "Yes, 다음 영역에서 사용: {...}"
**출처:** 코드
**선택지:** A. Analyst 발견값 그대로(추천) / B. 추가 항목 있음 / C. 외부 API 사용 안 함

### Q3. 자주 깨지는 부분

**추천:** Analyst 후보 (lockfile, generated code, native binding 등) + "수정 시 자주 깨지는 부분은 작업 중 추가 누적"
**출처:** 코드 + 일반 권장
**도구:** plain text — 사용자 자유 추가

### Q4. README에는 없지만 AI가 꼭 알아야 하는 관례

**추천 예시:** "테스트 데이터는 fixtures/ 아래에 둔다", "secret은 절대 커밋 금지" 등
**출처:** 일반 권장
**도구:** plain text — 사용자 자유 서술 또는 "없음" 응답
